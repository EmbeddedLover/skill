# MRD 到 PRD 映射规则

把 MRD 内容转换成 PRD 内容时，使用以下映射。

| MRD 内容 | PRD 去向 |
|---|---|
| 市场背景 | 产品背景与机会 |
| 市场痛点 | 问题定义与用户痛点 |
| 目标细分人群 | 目标用户与用户画像 |
| 使用场景 | 用户场景与用户流程 |
| 业务目标 | 产品目标与成功指标 |
| 市场机会 | 产品定位与价值主张 |
| 竞品分析 | 差异化、需求与非目标 |
| 产品概念 | 方案概述与功能范围 |
| 需求优先级 | MVP 范围与分阶段路线图 |
| 约束条件 | 非功能需求与交付约束 |
| 风险 | 风险评估与应对方案 |
| 时间线 | 版本计划与里程碑 |

## 推导规则

- 将用户痛点转换为用户故事。
- 将业务目标转换为可衡量的成功指标。
- 将使用场景转换为流程、页面需求和交互需求。
- 将竞品缺口转换为差异化需求或明确非目标。
- 将约束转换为验收标准、技术要求或上线限制。
- 将风险转换为缓解方案。

## 质量规则

- 保持可追溯：重要 PRD 决策应能追溯到 MRD 事实；不能追溯时标记为假设。
- 不要过度扩写：MRD 只支持 MVP 范围时，不要扩写成臃肿的完整产品。
- 优先使用可衡量语言：尽量写清数值、状态、阈值和完成定义。

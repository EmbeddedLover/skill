# 智能硬件 PRD 增补规则

当 PRD 涉及智能硬件、IoT、嵌入式设备、可穿戴、键盘、传感器、家电或任意联网实体产品时，使用本参考。

## 必要心智

纯软件 PRD 不足以支撑智能硬件项目，但 PRD 也不应变成详细工程手册。PRD 应聚焦产品意图、用户可感知能力、可衡量约束、验收边界和跨团队决策。

在 PRD 中写选型要求和决策门槛。除非用户明确要求一体化交付文档，否则不要写最终器件型号、详细 BOM、工厂测试流程、认证测试计划或工程实现细节。

MRD 证据不完整时，值标记为 `TBD`；不要编造器件型号、BOM 成本、生产良率、认证状态或测试阈值。

## 额外澄清问题

只有缺失信息会阻塞可用硬件 PRD 时才提问：

1. 产品形态和预期使用环境是什么？
2. 是否有必须使用的硬件部件或已知供应商约束？
3. 设备必须连接哪些平台，例如手机 App、桌面客户端、云端、BLE、USB、Wi-Fi 或蜂窝网络？
4. 当前阶段是概念、EVT、DVT、PVT、试产还是量产？
5. 需要考虑哪些认证区域、目标成本、目标售价和上市时间？

## PRD 边界规则

使用以下边界：

| 写入 PRD | 移到配套文档 |
|---|---|
| 产品能力要求 | 具体器件型号 |
| 用户可感知硬件约束 | 详细原理图或电路设计 |
| 选型标准和待定决策 | 完整 BOM 和供应商报价 |
| 关键接口要求 | 详细固件协议寄存器 |
| 高层 EVT/DVT/PVT 阶段门槛 | 工厂工站流程 |
| 认证适用性与上市门槛 | 完整认证测试计划 |
| 质量目标和风险类别 | 可靠性测试配方和样本计划 |
| 售后政策要求 | 维修 SOP 和备件运营 |

如果用户只要求 PRD，将配套文档内容浓缩为 `配套文档建议`。

如果用户要求全套项目文档，应拆成独立文档，而不是全部塞进 PRD。

## 智能硬件必备 PRD 章节

在 `研发交付版` 或 `完整版` PRD 中加入以下章节，并保持在需求层级：

1. 硬件能力与规格约束
2. 固件与嵌入式能力要求
3. 通信与接口要求
4. App/客户端/云端协同要求
5. 结构、材料与工业设计约束
6. 电源、功耗与续航要求
7. 生产与测试边界要求
8. EVT/DVT/PVT 阶段门槛
9. 认证、法规与合规门槛
10. 质量、可靠性与售后目标
11. 选型待确认事项
12. 配套文档建议

## 硬件需求检查清单

以下内容写成能力要求或选型标准，不写成最终选型：

- 产品尺寸与重量
- 显示或指示要求
- 按键、触摸、旋钮、马达、触觉反馈、扬声器、麦克风
- 传感器与精度期望
- MCU/SoC 等级
- 内存与存储
- 电池容量与充电方式
- 连接方式：BLE、USB、Wi-Fi、NFC、蜂窝网络等
- 防水、防尘、跌落、振动、温度和湿度要求
- 材料、皮肤接触安全、人机工学和佩戴舒适性
- 颜色、表面处理和 ID 约束

## 固件与嵌入式需求检查清单

以下内容写成行为和验收要求：

- 启动流程和失效保护行为
- 传感器采样策略
- 电源模式和唤醒/休眠规则
- 数据缓存与离线存储
- 时间同步
- BLE/USB/Wi-Fi 协议行为
- OTA/DFU 升级
- 错误处理与恢复
- 本地日志与诊断数据
- 工厂模式和测试固件要求
- 如适用，加入签名固件、防回滚等安全要求

## 生产与质量边界检查清单

PRD 中只写阶段门槛和必需输出：

- EVT、DVT、PVT、试产、量产阶段目标
- 工程样机和试产数量；未提供时标记为 `TBD`
- 良率目标；未提供时标记为 `TBD`
- 工厂测试覆盖类别
- 校准要求类别
- 可靠性要求类别
- 包装和外观要求类别
- 退换修分类类别

详细工站步骤、测试限值、测试治具、校准算法和样本量计划应移到配套文档。

## 认证与合规边界检查清单

PRD 中写适用性和上市门槛：

- 无线电和无线认证
- 电池与充电安全
- 电气安全
- 环保合规
- 数据隐私和敏感个人信息
- 涉及健康功能时的医疗器械边界
- 广告宣传和功能宣称合规
- 应用商店隐私要求

面向中国市场的智能硬件，应考虑 SRRC、CCC 相关要求、电池安全、蓝牙认证、RoHS/环保要求、个人信息保护合规和医疗器械边界审查是否适用。不确定时标记为 `TBD`。

具体标准、实验室报价、测试周期、送样数量和提交流程应移到认证合规清单。

## 选型边界

PRD 中的选型相关内容应写成：

- 产品必须支持 [能力]。
- 器件选型必须满足 [场景/约束]。
- [麦克风 / 无线 SoC / 电池 / 传感器 / 连接器] 的最终选型为 `TBD`，必须在 [EVT/DVT/PVT 阶段门槛] 前关闭。
- 选定方案必须通过 [用户可感知测试或工程阶段门槛] 验证。

避免写入：

- 具体器件型号
- 供应商名称和报价
- 完整 BOM 成本表
- 电路级建议
- 寄存器级固件细节
- 详细天线/RF layout 指令

## 配套文档建议

相关时，加入简短章节列出建议的后续文档：

1. 《硬件需求规格 HRS》
2. 《器件选型评估表》
3. 《固件需求规格 FRS》
4. 《通信协议规格》
5. 《EVT/DVT/PVT 测试验证计划》
6. 《认证合规清单》
7. 《BOM/供应链与成本评估》
8. 《生产测试规范》
9. 《售后与维修策略》

## 输出规则

如果用户询问某份 PRD 是否足以支撑智能硬件项目，应按以上章节检查并指出缺口。若用户要求生成或优化 PRD，应加入需求级智能硬件章节，并把深层工程内容移到 `配套文档建议`，除非用户明确要求展开。

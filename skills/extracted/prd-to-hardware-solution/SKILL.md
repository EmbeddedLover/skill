# PRD 转硬件方案

## 概览

使用本 skill 将 PRD 转换成一份完整硬件方案文档。流程必须分两阶段：先调研并比较候选方案方向，暂停等待用户确认；再生成最终整合版硬件方案报告。

## 必读参考

- 读取 `references/workflow.md`，遵守两阶段流程和必须暂停点。
- 起草最终报告前读取 `references/output-template.md`。
- 搜索或写入任何型号、价格、库存、采购链接或供应商主张前，读取 `references/evidence-rules.md`。
- 按产品类型读取 `references/category-checklists.md`，识别关键器件类别。

## 工作流程

1. 读取 PRD，提取硬件需求、约束、目标用户、MVP 范围、非目标、成本带、法规区域、接口、电源限制和验证门槛。
2. 识别产品类型和关键器件类别。
3. 联网查证当前来源，对比国内外候选器件和方案方向。
4. 输出候选方案方向比较，并要求用户选择一个方向后再定稿硬件方案。
5. 用户确认后，再次查证具体型号、官方资料、数据手册、立创/LCSC 链接、淘宝链接、价格、库存和可得性证据。
6. 生成一份最终硬件方案文档，不拆成多个文件。

## 输出规则

- 除非用户指定其它路径，最终输出必须是一个 Markdown 文件：`docs/hardware/[product]-hardware-solution.md`。
- 候选方案比较、已选方向、采购证据、价格评估和验证计划都要放在同一个文件里。
- 不要编造型号、价格、库存、链接、认证或供应商主张。
- 找不到当前采购证据时，写 `未找到可靠来源` 并列出搜索缺口。
- 所有价格都要标注查询日期。
- 淘宝可靠商品页不可访问时，可以使用搜索链接，但必须标注为搜索链接，而不是已验证商品。

## 暂停规则

输出候选方案方向比较后暂停，并要求用户确认一个方向：

- 成熟均衡量产方案
- 国产低成本方案
- 快速 EVT 打样方案
- 高性能/高扩展方案
- 多方案并行

除非用户明确要求自动选择方向，否则在用户确认方向前，不要生成最终完整硬件方案。

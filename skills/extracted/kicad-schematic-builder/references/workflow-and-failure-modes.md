## 适用目标

这套流程适合以下工作：

- 根据参考图片重建模块化 KiCad 原理图；
- 创建 MCU 最小系统、接口板、传感器板和电源小板；
- 先完成器件摆放，再逐步加入电源、标签和导线；
- 修改已有 `.kicad_sch` 并保持页面结构；
- 修复“看上去连上但 ERC 仍报错”的连接问题；
- 为原理图生成 SVG、PNG、ERC 报告和网络表。

它不替代芯片数据手册，也不自动授权进行 PCB 布局、布线或生产文件输出。

## 确认门禁与参考图读取

门禁选择、任务模式和参考图读取条件以 `SKILL.md` 为准。本参考文件只保留实现细节和失效模式，避免与主流程形成两套定义。

参考图不能替代电气需求。使用参考图时仍需输出 `继承 / 调整 / 忽略` 判断，不得自动复制当前需求未包含的外围电路。

## 从需求到工程的完整过程

### 1. 固定边界

先把需求拆成四类：

1. 必须包含的模块和器件；
2. 明确排除的外围模块；
3. 当前阶段允许的对象，例如仅摆放、允许标签、允许布线；
4. 最终验收方式，例如 KiCad 版本、ERC、预览和网络核对。

不要因为参考图中存在 USB、串口、显示器或自动下载电路，就默认加入未被请求的模块。

### 2. 建立器件与网络表

在打开或生成原理图之前，先列出：

| 项目 | 内容 |
|---|---|
| 引用号 | U1、J1、C1 等 |
| KiCad 符号 | 完整 `lib_id` |
| 显示值 | 精确型号或参数 |
| 封装 | 本机库中真实存在的封装 |
| 模块 | 电源、时钟、复位等 |
| 本地连接 | 模块内短线 |
| 跨模块网络 | 同名标签 |
| 验证节点 | MCU 引脚、接口引脚、功能器件 |

器件型号和封装要分别确认。符号显示 `STM32F103C8T6` 不代表已经绑定 `LQFP-48_7x7mm_P0.5mm`。

### 3. 先创建可解析基线

先生成最小、可被目标 KiCad 版本加载的工程，再逐步增加内容。每完成一个高风险阶段就导出一次 SVG：

1. 项目和空白页面；
2. 器件与文字；
3. 电源符号与标签；
4. 导线和结点；
5. 最终标题栏与预览。

这种增量方式可以快速定位是符号缓存、实例、坐标、导线还是文本导致解析失败。

### 4. 分阶段实现

推荐顺序：

1. 放置全部器件并校验引用号；
2. 调整模块边框、标题和器件属性；
3. 统一电源与功能网络名称；
4. 放置电源符号、GND 和标签；
5. 绘制模块内短线；
6. 导出网络表核对跨模块网络；
7. 跑 ERC 并修复；
8. 导出 SVG/PNG 做最终视觉检查。

不要在器件位置还未稳定时大量画线。

## 模块化布局方法

### 页面分区

- 主控放在页面中央或视觉中心区域。
- 电源、时钟、复位、启动、调试、指示灯和接口分别成组。
- 模块边框主要用于阅读，不应成为导线必须跨越的障碍。
- 页面底部和右下角为 KiCad 标题栏预留空间。

### 器件摆放

- 信号源、串联器件和负载沿同一水平中心线排列。
- 去耦电容采用上电源轨、下 GND 轨。
- 晶振位于两个 MCU 时钟网络之间，负载电容向下接地。
- 复位网络以 `NRST` 水平线形成 T 形，上拉向上，按键和电容接地。
- 磁珠与 VDDA 过滤使用单一水平主线，过滤电容垂直接地。
- 连接器标签应朝模块内部或页面空白区域展开。

### 间距

- 导线与器件外框至少留一个当前网格间距。
- 导线与模块标题、说明文字至少留两个网格间距。
- 标签必须与引脚编号分离。MCU 两侧可增加 2.54 mm 左右的短线后再放标签。
- 空间不足时移动器件或文字，不要增加蛇形绕线。

## 网络命名与接口映射

### 命名原则

- 电源使用统一名称，例如 `+5V`、`+3V3`、`GND`。
- 功能网络使用功能名，例如 `SWDIO`、`SWCLK`、`NRST`、`BOOT0`。
- 普通 GPIO 保留 MCU 端口名，例如 `PA0`、`PB12`。
- 不要让 `PA13` 和 `SWDIO` 同时作为两个不同网络存在于同一设计意图中。
- 不要混用 `3V3`、`+3V3`、`VCC_3V3`，除非它们确实是隔离电源域。

### 接口映射

先建立接口 pin map，再创建标签。完成后从 KiCad 网络表反查：

- J2.2 是否与 U1 的 SWDIO 引脚同网；
- J3.17 是否也在 SWDIO 网络；
- LED 网络是否同时包含 MCU、LED 和扩展接口；
- LSE/HSE 网络是否同时包含晶振、电容和 MCU；
- VBAT 是否按需求接入独立电池或主 3.3 V。

连接器上的普通说明文字不产生网络。只有标签、电源符号和真实导线参与电气连接。

## 低层坐标与连接规则

### 不要依赖视觉接触

KiCad 中，导线端点必须落在精确引脚端点。相差 1.27 mm 时，预览可能仍像连在一起，但 ERC 会报告：

- `pin_not_connected`；
- `label_dangling`；
- `unconnected_wire_endpoint`。

导线经过引脚附近或穿过符号图形不等于连接。

### 分割母线

当多个电容连接到一条母线时，推荐在每个电容引脚处拆分线段：

```text
C5.x -> C6.x -> C7.x -> C8.x -> C9.x
```

不要只画一条从 C5 到 C9 的长线并假设中间引脚一定建立连接。真实 T 形分支处放置结点。

### 旋转与镜像

若直接编辑 KiCad S 表达式，必须处理实例旋转和镜像。设库符号引脚坐标为 `(rx, ry)`，实例原点为 `(ix, iy)`：

1. `mirror y` 时令 `rx = -rx`；
2. `mirror x` 时令 `ry = -ry`；
3. 在符号坐标系中按实例角度旋转；
4. 转换到页面坐标时，页面 Y 方向与库坐标相反；
5. 最终坐标为 `(ix + rotated_x, iy - rotated_y)`。

固定写死的线段坐标在移动或旋转器件后很容易失效。优先根据引用号、`lib_id` 和引脚号计算坐标。

### 线段规则

- 所有线段应满足 `x1 == x2` 或 `y1 == y2`。
- 删除 `(x1, y1) == (x2, y2)` 的零长度线段。
- 模块间使用标签，避免几十毫米的贯穿长线。
- 只有真实分支使用结点，不在普通直线或交叉但不连接的位置放结点。

## 电源域与 ERC

### 外部输入

外部连接器提供的正电源和回流 GND 都可能需要 `PWR_FLAG`，否则 KiCad 只看到电源输入和无源器件，看不到电源输出。

### 稳压输出

AMS1117 等稳压器输出脚通常是 `power_out`，其主输出网络无需额外 `PWR_FLAG`。重复放置电源标志会掩盖真正的供电拓扑。

### 磁珠后的模拟电源

磁珠是无源器件。即使磁珠输入接在由稳压器驱动的 `+3V3` 上，KiCad 也可能把输出侧 `VDDA` 视为未驱动的独立电源域。此时可在磁珠输出侧放置 `PWR_FLAG`，同时保持 `VDDA` 与 `+3V3` 为两个不同网络。

### GND

GND 符号在 KiCad 中是 `power_in`，并不自动成为电源输出。外部输入场景中，GND 回路也需要明确的电源源声明。

### ERC 原则

- 先理解错误，再决定修改拓扑、增加标志或记录豁免。
- 不要通过隐藏引脚、批量忽略规则或删除电源符号来追求表面上的零错误。
- 严格零网络的“器件摆放版”出现未连接引脚是预期现象；一旦任务进入布线阶段，未连接的电源脚不应再被当作预期。

## 视觉检查规则

导出 SVG 或 PNG 后检查：

1. MCU 顶部电源脚文字是否拥挤；
2. MCU 两侧标签是否覆盖引脚号；
3. 晶振左右标签是否互相碰撞；
4. 复位和 BOOT0 是否存在斜线；
5. 排针最后几行标签是否与说明文字重叠；
6. GND 符号是否压住电容值；
7. 磁珠属性文字是否穿过导线；
8. 模块边框是否穿过标题栏或器件；
9. 所有导线是否停留在所属模块内；
10. 预览是否与最终保存时间一致。

属性文字不是必须全部显示。紧凑区域可以隐藏磁珠等器件的引用号和值，但必须在工程属性和 BOM 数据中保留正确内容。

## 验证顺序

推荐按以下顺序执行：

1. `kicad-cli sch export svg`：验证语法、符号缓存和可渲染性；
2. 静态线段检查：发现斜线、零长度线和异常长线；
3. `kicad-cli sch erc`：发现真实连接和电源域问题；
4. `kicad-cli sch export netlist`：核对同名标签形成的跨模块网络；
5. 生成 PNG 并进行视觉检查；
6. 检查引用号、值、封装和输出文件；
7. 清理一次性脚本和临时验证文件。

优先使用 `kicadsexpr` 网络表。KiCad 10.0.5 在部分 Windows 中文环境中导出的 `kicadxml` 可能声明 UTF-8 但产生不严格的中文属性编码，不应把该现象误判为 `.kicad_sch` 损坏。

## 本次实践暴露的失效模式

### 1. 导线看似接触但实际悬空

症状：预览正常，ERC 出现几十个 `pin_not_connected`。

原因：固定坐标没有落在旋转后引脚端点，常见偏差为 1.27 mm 或 2.54 mm。

处理：从缓存符号读取引脚相对坐标，再结合实例原点、旋转和镜像计算绝对坐标。

### 2. 母线穿过中间引脚但未连接

症状：母线两端电容正常，中间电容未连接。

原因：线段没有在中间引脚处拆分，或缺少真实分支结点。

处理：在每个引脚坐标处分段，并在 T 形连接处放结点。

### 3. 固定连接列表生成斜线

症状：脚本用两个端点直接生成导线，复位或 BOOT0 出现对角线。

原因：两个器件引脚不在同一 X 或 Y 坐标。

处理：增加一个 90 度转角点，或移动器件使串联支路对齐；最终静态检查所有线段。

### 4. MCU 电源脚区域过密

症状：多个 `+3V3`、VDD、VBAT、VDDA 文字覆盖引脚号。

处理：数字电源脚使用一条短本地母线和单个电源符号；VDDA 使用独立短线和标签；不要在每个相邻引脚上重复放置长标签。

### 5. 磁珠封装不存在

症状：ERC 或封装检查报告库中找不到指定封装。

原因：封装名称来自其他 KiCad 版本或记忆中的近似名称。

处理：列出本机 `.pretty` 目录中的实际文件，再绑定真实存在的封装。

### 6. 为消除 ERC 误用 PWR_FLAG

症状：所有电源网上都放置标志，ERC 为零但供电拓扑失真。

处理：区分外部输入、稳压器输出和磁珠隔离后的电源域。主 `+3V3` 由稳压器 `power_out` 驱动时不额外放标志。

### 7. 清理脚本破坏用户文件

风险：为了重新生成对象而删除整个工程或覆盖无关项目。

处理：只删除当前脚本明确拥有的导线、标签、结点或临时实例；不修改其他工程，不使用破坏性 Git 命令。

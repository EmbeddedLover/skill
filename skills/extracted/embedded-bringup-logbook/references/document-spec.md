# 字段定义与取值约定

## 三种编号不可混用

台账里最容易出错的地方。同一根针有三个不同的标识，混用会导致接线与代码对不上。

**物理脚号** — 排针上按位置数的序号（如 40Pin 排针的 1 到 40）。用途：决定插哪个孔。奇偶分列排布时注意左右。

**GPIO 号** — 芯片对该引脚的内部编号。用途：写代码时填的参数。

**网络名** — 原理图里这根线的正式名称（如 `VDD_3V3`）。用途：与原理图交叉核对时的唯一锚点。

物理脚号与 GPIO 号不存在简单换算关系，因为电源和地占位置但无 GPIO 号。必须逐个查表。

## PINMAP.md 字段

| 字段 | 取值 | 说明 |
|------|------|------|
| 外设 | 自定名称 | 与 `peripherals/` 下文件名保持一致 |
| 物理脚号 | 数字 | 排针位置序号 |
| GPIO号 | `GPIOxx` 或 `—` | 电源/地填 `—` |
| 复用功能 | 官方功能名 | 照抄官方引脚图写法，如 `IIC1_SDA`。不要自行改写大小写或缩写 |
| 方向 | `输入` / `输出` / `双向` | 双向如 I2C 的 SDA |
| 电平域 | 如 `3.3V` | 与外设工作电压比对，不一致需电平转换 |
| 板载占用风险 | `无` / 具体说明 | 官方图带 `!` 标记的必须写明占用者 |
| 状态 | `规划中` / `待验证` / `已验证` / `已放弃` | 只有实测通过才能标 `已验证` |
| 证据 | `[实测]` / `[官方]` / `[推测]` | 不允许留空 |
| 备注 | 自由文本 | 手册页码、坑、依赖关系 |

## 证据等级判定

`[实测]` — 在本人这块板子上运行验证过。他人的成功案例不算。

`[官方]` — 厂商引脚图、原理图、官方例程、官方文档。注意标明版本，官方资料也会有勘误。

`[推测]` — LLM 输出、论坛帖子、同系列型号类推、自己的推断。这类条目的作用是记录待验证线索，不是可用配置。

等级只能通过实测升级，不能因为"看起来很合理"而升级。

## 状态流转

```text
规划中 → 待验证 → 已验证
                ↓
             已放弃（记录原因，写入 PITFALLS.md 已排除的错误假设）
```

分配引脚后即为 `待验证`。实测通过才改 `已验证`，同时补记验证日期与验证方式——没有验证方式的"已验证"无法复现，等于没验证。

## 日期与版本

日期一律绝对格式 `YYYY-MM-DD`。禁止"上周""前几天""最近"，这类表述在文档存放三个月后失去意义。

版本号写精确值。写"最新版"等于没写，因为"最新"随时间变化。

## 缺失信息的写法

不确定的一律写 `待核对`，并在备注注明查证途径：手册页码、需要哪个原理图页、需要实测什么。

禁止用看似合理的猜测填空。台账的价值在于可信，一条编造的记录会让整份文档失去意义——因为你无法再区分哪些是真的。
